# 设计：口语陪练（待确认，未实现）

用户选一个场景（点餐、面试、出差），和陪练 agent 用英语对话。说话时只有陪练在前台回答，保证不卡；评估 agent 在后台逐句检查语法和用词；练完后规划 agent 根据弱项安排下一课。

## 和其他两项的不同

会议记录、有声内容是“提交了等结果”，口语陪练是**实时对话**。所以多 agent 分成前台和后台两部分，前台必须和现在的语音对话一样快：

```mermaid
flowchart TB
    subgraph 前台：每句话
        M[用户说英语] --> ASR["SenseVoice<br/>自动识别中英文"]
        ASR --> TU["陪练 agent<br/>扮演场景角色，回答要短"]
        TU --> TTS["英语音色播报<br/>edge-tts en-US"]
    end
    subgraph 后台：不挡回答
        ASR -.->|同一句话| EV["评估 agent<br/>语法、用词、更地道的说法"]
        EV --> UI["页面右侧逐句批注"]
    end
    subgraph 练完后：后台任务
        END[点“结束练习”] --> RP["报告 agent<br/>汇总本次错误"]
        RP --> PL["规划 agent<br/>下一课场景和重点"]
        PL --> MEM[(练习记录)]
    end
```

评估 agent 在陪练回答的**同时**运行，不等它，不占前台时间；批注晚一两秒出现在页面上即可。

## agent 分工

| agent | 何时运行 | 输入 | 输出 | 预算 |
|---|---|---|---|---|
| `tutor` | 每句话，前台 | 场景、最近几轮对话 | 角色回答，最多两句；用户卡住时给提示 | 用主对话的通道，不单独限额 |
| `evaluator` | 每句话，后台 | 用户这一句 + 上下文 | JSON：错误类型、原句、改正、更地道的说法；没错就空 | 每句 0.005 元 |
| `report` | 练完 | 本次全部批注 | 本次总结：最常见的三类错误、进步 | 0.03 元 |
| `planner` | 练完 | 总结 + 历史练习记录 | 下一课：场景、重点句型、三个热身句 | 0.03 元 |

`tutor` 需要改动现有的语音对话：在 WebSocket 上加一个“陪练模式”，换系统提示和音色、关掉工具；不是新开后台任务。这一项是三个业务里唯一要碰实时语音链路的。

## 发音评分

SenseVoice 只给文字，不给发音分。三个选择：

| 方案 | 效果 | 花费 | 工作量 |
|---|---|---|---|
| A. 第一版不做发音分，只评语法和用词 | 能用，但少了口语练习最想要的一项 | 0 | 最小 |
| B. 跟读题：给一句让用户读，比对 SenseVoice 听到的和原句，读错的词标红 | 粗略但直观 | 0 | 小 |
| C. 接入云端口语评测（讯飞、腾讯云等都有），给音素级分数 | 最好 | 按次收费，需要选服务商 | 中，要账号和 Key |

建议第一版 **A + B**，有用户和收入后再接 C。

## 数据与接口

- 每用户新表 `practice_sessions`（场景、开始结束时间、批注 JSON、总结、下一课），放在 `agent.db`。
- WebSocket 新消息：`practice_start {scenario}`、`practice_stop`；服务器推 `practice_note`（批注）。
- 页面：新增“口语陪练”卡片：选场景、开始/结束、对话区旁的批注列、历史练习和“下一课”。

## 花费估算

20 分钟练习约 40 句：陪练 40 次调用（缓存命中率高）约 0.03 元，评估 40 次约 0.04 元，报告加规划约 0.02 元，合计约 **0.1 元/次练习**。

## 风险

| 风险 | 对策 |
|---|---|
| 识别把英语听成中文 | SenseVoice 指定语言为英语（陪练模式下） |
| 评估太挑剔，打击积极性 | 每句最多指出一处最重要的错误 |
| 改动实时链路影响普通对话 | 陪练模式是独立分支，普通模式代码路径不变，现有测试全部保留 |

## 测试计划

- 假模型：陪练回答不等评估；评估 JSON 解析；每句最多一条批注；结束后报告 → 规划串联。
- WebSocket：陪练模式下工具被关掉、普通模式不受影响。
- 声音相关的测试按之前的约定，等新麦克风到了再测；在那之前用录好的英语音频文件喂给识别。
